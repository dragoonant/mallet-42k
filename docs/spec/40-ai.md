# 40 — AI opponent

The AI is a `Decider` (00-architecture §3). It sees only `PlayerView`, answers every `PendingDecision`
with an `Action`, and uses engine query functions for legality and measurement. It never touches engine
internals and never rolls dice itself (Monte Carlo uses its own local RNG on a copied state).

## 1. Structure

```
src/ai/
  decider.ts        AiDecider(difficulty): Decider — dispatch on pending.kind
  damage.ts         expected damage calculator (§2), sampler for Monte Carlo
  value.ts          target value, objective value, threat maps
  roles.ts          role planner (§4)
  phases/{deploy,command,move,shoot,charge,fight,stratagem,allocate}.ts
  mc.ts             Monte Carlo evaluator using engine.step on cloned state with local rng
  difficulty.ts     knobs (§6)
  tune/             harness (§7)
```

Dispatch table (`pending.kind` → module): `deployUnit`→deploy, `chooseUnitToActivate`/`declareMove`/`moveUnit`→move (or shoot/charge/fight by phase), `declareTargets`→shoot, `allocateAttack`→allocate, `declareCharge`/`chargeMove`→charge, `chooseFightUnit`/`pileIn`/`consolidate`→fight, `stratagemWindow`/`reactionWindow`/`commandReroll`→stratagem, `confirm`→ok, `chooseOption`→generic scorer.
Every phase decider returns the best-scored action among candidates that pass `engine.validate`; if none pass, `pass` (when allowed) or `legal[0]`.

## 2. Expected damage calculator

`expectedDamage(att: UnitView, weapons: WeaponUse[], tgt: UnitView, ctx): DamageEstimate` where `ctx = {range, inCover, charged, oathTarget, activeMods}`. Every rule effect the engine applies is mirrored here; abilities are read from the same data descriptors (`trigger`/`when`/`effect`) so the calculator stays in sync with the data. Bespoke `code` hooks provide an optional `estimate()` in the hook registry; absent that the AI ignores them.

| Step | Formula |
|---|---|
| attacks | `n = models · E[A]`; RAPID_FIRE +value if `range ≤ half`; BLAST +⌊targetModels/5⌋ (min 3 vs 6+ models); EXTRA_ATTACKS added separately |
| hit | `pHit = clamp((7 − skill + hitMod)/6, 1/6, 5/6)`; TORRENT → 1; hitMod capped to [−1, +1]. Re-roll ones: `p += p/6`; re-roll fails: `p += (1−p)·p`. `pCritHit = 1/6` (5/6 if lethal/sustained threshold lowered by `lethalOn`) |
| sustained / lethal | `hits = n·pHit + n·pCritHit·E[SUSTAINED]`; LETHAL: `autoWounds = n·pCritHit`, remaining hits wound normally |
| wound target | S vs T: `S ≥ 2T → 2+`, `S > T → 3+`, `S = T → 4+`, `S < T → 5+`, `S ≤ T/2 → 6+`; woundMod capped [−1, +1]; LANCE +1 on charge; ANTI-X: crit wound on `value+` vs keyword; TWIN_LINKED: re-roll fails |
| devastating | crit wounds → `mortal = E[D]` each, bypass saves; FNP still applies |
| save | `sv = min(Sv − AP', invuln)`; cover: `Sv − 1` for ranged unless (Sv ≤ 3 and AP = 0) or IGNORES_COVER; `pFail = clamp((sv − 1)/6, 0, 1)` (sv ≥ 7 → no save) |
| damage | `dmg = unsaved · E[D]`; MELTA +value if `range ≤ half`; damageReduction/halveDamage applied per instance; FNP: `× (1 − pFnp)` |
| kills | allocate expected damage model by model with overkill loss: `killed = ⌊unsaved · min(E[D], W)/W⌋` for multi-wound targets; `pKillUnit` from a normal approximation of total damage (mean, variance from binomial chain) |
| hazardous | expected self-loss `n_haz/6 · (3 dmg or 1 model)` subtracted from payoff |

Output: `{ attacks, hits, wounds, unsaved, mortals, damage, modelsKilled, pKillUnit, variance }`.
`sampleDamage(att, weapons, tgt, ctx, rng)` draws one outcome with the same rules (used by §5).
Tests: results must match the engine's empirical mean over 2 000 seeded runs within 3 % (60-testing).

## 3. Values

| Quantity | Definition |
|---|---|
| `unitValue(u)` | `points(u) · woundsRemaining/woundsTotal · roleMult` where roleMult: CHARACTER 1.5, leader-attached 1.3, holding objective 1.3, BATTLELINE 1.1 |
| `threat(u→v)` | `expectedDamage(u, allWeapons, v)` at `u`'s reach next turn (`M + range`, or `M + 2D6 mean 7` for melee) |
| `threatMap(pos)` | Σ over enemy units of expected damage to a probe unit at `pos`, discounted by `pReach` |
| `objectiveValue(o, round)` | `vpPotential(o) · (roundsLeft)`; ×1.5 if currently enemy-held, ×0.6 if safely held (OC margin ≥ 5 and no enemy within 12) |
| `coverValue(pos)` | expected damage reduction from Benefit of Cover against known enemy shooters |
| `vpDelta` | VP change implied by objective control changes at next scoring window |

## 4. Role planner

Runs at the start of the AI's turn (and once after deployment). Assigns each unit one role for the turn; phase deciders weight their utilities by role.

| Role | Assign when | Utility weights (obj, threatAvoid, damage, chargePot) |
|---|---|---|
| `hold` | high OC per point, low damage output, or already on a needed objective | 1.0, 0.8, 0.3, 0.1 |
| `screen` | cheap, expendable, enemy melee threat high, protects a `hold` or `strike` unit | 0.4, 0.2, 0.2, 0.3 (+ blocking value: reduces enemy charge paths to protected units) |
| `strike` | high damage output; a target exists with `pKillUnit ≥ 0.4` or vpDelta > 0 | 0.3, 0.4, 1.0, 1.0 |

Algorithm: enumerate objectives needing holders (by `objectiveValue`), greedily assign the cheapest sufficient `hold` unit (OC ≥ enemy OC in range + 1) considering travel time (`dist/M` turns); remaining units become `strike` if any target scores > threshold, else `screen`. Re-planned every turn; lookahead ≥ 1 adds a one-turn projection of enemy moves (they move `M` toward their nearest objective/target).

## 5. Per-phase deciders

| Phase / decision | Candidates | Score |
|---|---|---|
| Deployment | positions in own zone: on/near home objectives, behind obscuring terrain, ≥ 9 from zone edge for reserves logic | `objectiveValue` + `coverValue` − `threatMap` − spread penalty |
| Command: battle-shock | n/a (rolls are automatic) | — |
| Command: CP stratagem | see stratagems | |
| Movement | per unit: sample points on rings radius {0, M/2, M, M+3.5 (advance)} × 16 directions, plus the nearest point to each objective and the best-cover point within M; move types normal/advance/fallBack/stationary; formation = models packed in coherency around the chosen anchor; validate | `w.obj·objectiveValue` + `w.threat·(−threatMap)` + `w.cover·coverValue` + `w.charge·chargePotential` (Σ over targets `pCharge·payoff` from next-phase estimate) − advance penalty if it forfeits shooting/charging (unless ASSAULT); fall back only if `expected loss staying > expected value of leaving` |
| Shooting: unit order | units sorted by (damage potential desc) | each unit shoots into a state updated with previous expected kills |
| Shooting: targets | for each weapon group: visible+in-range enemy units (engine query) | `E[damage]·unitValue/points + killBonus·pKillUnit + vpDelta`; weapons default to one target, split only when a pistol/heavy weapon has a better own target; avoid targets already expected dead |
| Charge | per unit: targets within 12 with LoS legality per engine | `pCharge(needed)` from 2D6 table (needed = shortest legal path − 1 engagement, with terrain) × `payoff` where payoff = fight damage − expected return damage + objective flip + tie-up value; Monte Carlo (§6) when `0.3 < pCharge < 0.8` or payoff variance high; declare multi-target charges only when `pCharge` drops < 10 % |
| Fight: unit order | own units eligible | kill priority: highest `pKillUnit·unitValue` first; units that might die to enemy activation go earlier |
| Fight: pile-in / consolidate | positions within 3 | maximise models in engagement with chosen target; consolidate onto objective or into another enemy if that pins a shooter |
| Wound allocation | models | protect champion/leader last unless the unit is doomed; pick already-wounded model when the rule allows |
| Stratagems | legal stratagems in the window | `Δ = utility(with) − utility(without)` evaluated via §2 estimates; use if `Δ ≥ threshold(cp, roundsLeft)` where `threshold = 0.6·avgTurnValue / cpRemaining · (1 + 0.15·roundsLeft)`; Overwatch and re-roll go through the same rule (command re-roll Δ = value gain × p(improved roll)) |

Charge probability table (2D6 ≥ n): 2:1.00 3:.972 4:.917 5:.833 6:.722 7:.583 8:.417 9:.278 10:.167 11:.083 12:.028.

## 6. Monte Carlo

`mcEvaluate(state, action, N, horizon)`: clone `PlayerView`-consistent state (hidden info sampled uniformly), run `engine.step` with a local `SeededRng` for the action and then a fast policy (tier-1 deciders with zero noise) for both sides until `horizon` phases; score = `VP diff + 0.02·(Σ own unitValue − Σ enemy unitValue)`. N by difficulty (§7), cap 1.5 s wall time per decision, run in a worker in the client. Used for: charge declarations, stratagem use with cost ≥ 2 CP or `|Δ|` within 20 % of threshold, fall-back decisions.

## 7. Difficulty

| Knob | easy | normal | hard |
|---|---|---|---|
| score noise (Gaussian σ as fraction of best score) | 0.35 | 0.12 | 0.0 |
| lookahead (role planner projection turns) | 0 | 1 | 1 |
| Monte Carlo N | 0 (formulas only) | 100 | 400 |
| stratagem threshold multiplier | 1.5 | 1.0 | 0.8 |
| candidate positions per unit | 8 | 24 | 48 |
| target mistakes | picks 2nd-best target 20 % of the time | none | none |

## 8. Tuning harness (`npm run ai:tune`)

Runs headless games (tools/sim) with configurable deciders per side, N games, seeds `s0..sN`.

| Metric | Target (M5) |
|---|---|
| win rate vs random-legal bot (normal) | ≥ 95 % over 100 games |
| win rate hard vs easy | ≥ 75 % |
| self-play mirror (A vs A, sides swapped per seed pair) | 45–55 % per side (no side bias) |
| game length | all games end by round 5; median decision time < 80 ms |
| decision rejections | 0 rejected actions from the AI per game (any rejection is a bug) |
| VP per game (normal vs normal) | mean 30–60 (sanity: objectives are being played) |
| profile | p99 decision < 300 ms, MC decisions < 1.5 s |

Output: `tune-report.json` `{config, games, winRate, meanVp, meanRounds, p50ms, p99ms, rejections}`; CI runs the 20-game smoke variant.
